# Qiita 続編向け: 実運用・比較・導入ポイント

このページは、前回記事「MarkdownからExcelのテスト仕様書を作成するツールを作りました」の続編として、そのまま転用しやすい素材をまとめたものです。

## 改修背景（AI時代のテスト仕様書運用）

AI 活用が進む中で、テスト仕様書も **機械的に扱いやすいテキスト形式（Markdown）** で管理する価値が高まっています。  
Markdown であれば差分レビューや履歴管理がしやすく、生成 AI による下書き・要約・観点整理とも相性が良いためです。  
一方で、現場では提出・共有フォーマットとして Excel が求められるケースが依然多く、**Markdown を正として管理しつつ Excel を生成する** 運用が実践的な落としどころになります。

## 前回記事との差分（今回の切り口）

- 前回: ツールの概要と基本的な使い方
- 今回: **実運用でどう回すか**、**手作業との比較**、**導入しやすさ** を中心に紹介

## 実運用の流れ（そのまま記事見出しにしやすい形）

1. テストケースを Markdown で記述する（レビューは Git で実施）
2. 既存の Excel フォーマットに合わせてテンプレートを用意する（`template/template.xlsx`）
3. CLI で Markdown 群を一括変換し、1 つの Excel を出力する
4. Excel を社内共有・提出に利用する
5. 仕様変更が出たら Markdown を更新し、再出力する

## 入力 Markdown の例（抜粋）

```markdown
---
spec_var: loginSpec
feature: ログイン
viewpoint: 正常系
---

# ログイン機能テスト

## 認証

### パスワード認証

#### 正しいID/パスワードでログイン

1. ログイン画面を開く
1. 正しいIDとパスワードを入力する
1. ログインボタンを押す

- [ ] ホーム画面が表示される
- [ ] ユーザー名がヘッダーに表示される
```

## 出力 Excel のイメージ（概念）

```
| No | 大項目 | 中項目         | 小項目                        | 確認手順         | 想定動作                       | 備考 |
|----|--------|----------------|-------------------------------|------------------|-------------------------------|------|
| 1  | 認証   | パスワード認証 | 正しいID/パスワードでログイン | 1. ログイン...   | ・ホーム画面が表示される      |      |
```

> 実際のレイアウトは `template/template.xlsx` の設計に従います。

## 手作業との比較（記事で使いやすい表）

| 観点 | 手作業で Excel 作成 | 本ツール（Markdown → Excel） |
|---|---|---|
| 変更のしやすさ | シート編集中心で差分追跡しづらい | Markdown なので Git 差分が見やすい |
| 再利用性 | 同じ整形作業を繰り返しがち | テンプレート化で繰り返しを削減 |
| チームレビュー | セル単位レビューが重い | PR ベースでレビューしやすい |
| 出力の統一性 | 人によって揺れやすい | テンプレートにより形式を統一しやすい |

## 導入メリット（短く伝える用）

- Markdown を正として管理し、Excel は配布フォーマットとして生成できる
- 既存 Excel テンプレートを活かせるため、現場の運用を壊しにくい
- 複数 Markdown を 1 ファイルにまとめて出力できる

## 使いどころ

- 「設計・レビューはテキスト管理したいが、提出は Excel 必須」の現場
- テストケースの更新頻度が高く、Excel 手修正コストが高いチーム
- 既存の帳票フォーマットを維持したまま運用改善したいケース

## 実装上の工夫として紹介しやすいポイント

- Markdown を AST 解析し、見出し/手順/期待値/備考を構造化して抽出
- 出力責務を JXls テンプレートに分離し、コード変更なしでレイアウト変更に対応
- front matter（`spec_var` とユーザ定義変数）でテンプレート連携を柔軟化
- テストケース単位でカスタム変数（3 列テーブル）を持てる設計
